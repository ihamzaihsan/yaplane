# Standard and demo runs

Standard startup creates an empty forum with the five default topics. Demo content is opt-in and uses separate storage. Database files and uploaded files are excluded from Git and Docker build contexts. Existing uploaded images are left on disk.

## Standard run with Docker

```powershell
docker compose up --build -d
```

Open **https://localhost:8080** and register an account. The image generates a localhost development certificate; accept the browser's self-signed certificate warning for local use. Database and upload volumes persist across restarts.

```powershell
docker compose down
```

This stops the application without clearing its data. Docker Compose reads optional settings from `.env`; the native Go application uses shell environment variables instead.

## Demo run with Docker

Use a separate Compose project so demo data never enters the standard forum's volumes. Both versions default to port 8080; the project name isolates storage but does not change the port. With `HOST_PORT=8080` and `OAUTH_BASE_URL=https://localhost:8080` in `.env`, stop the standard app before starting the demo:

```powershell
docker compose down
docker compose -p yaplane-community-demo build
docker compose -p yaplane-community-demo run --rm forum /app/seed-demo
docker compose -p yaplane-community-demo up -d
```

Open **https://localhost:8080**. The seed command creates **five fictional accounts, 15 posts, 30 replies, and 90 reactions**. Post reaction and comment notifications are generated by the existing database triggers. The shared accounts have ordinary member permissions.

The homepage displays the latest ten posts; older demo posts remain accessible through topics and account activity.

Seed only before starting a fresh demo project. The command refuses an existing database file, including an empty initialized database, and never overwrites it. Subsequent starts need only `docker compose -p yaplane-community-demo up -d` with your chosen port settings. Stop that project using `docker compose -p yaplane-community-demo down` before switching back to the standard app on port 8080.

The Docker certificate is for local development. Supply trusted certificate/key paths for public hosting. Google/GitHub sign-in still requires your own provider credentials and callbacks matching the chosen HTTPS origin; shared demo accounts work without them.

## Run both versions together

Separate projects cannot bind the same host address and port at the same time. Keep the standard app on port 8080 and optionally use port 8081 for the demo. In PowerShell:

```powershell
$env:HOST_PORT = '8081'
$env:OAUTH_BASE_URL = 'https://localhost:8081'
docker compose -p yaplane-community-demo up --build -d
Remove-Item Env:HOST_PORT
Remove-Item Env:OAUTH_BASE_URL
```

Seed a fresh demo before running `up`, using the first-setup commands above with these overrides set. For an existing demo, skip seeding. Open **https://localhost:8081**. If OAuth is enabled, register callbacks at `https://localhost:8081/auth/google/callback` and/or `https://localhost:8081/auth/github/callback`.

Shell variables override `.env`. Set both overrides again whenever starting or recreating the demo on port 8081. In Git Bash, use `export HOST_PORT=8081 OAUTH_BASE_URL=https://localhost:8081` before the demo commands and `unset HOST_PORT OAUTH_BASE_URL` afterward. Both containers still listen on port 8080 internally; `HOST_PORT` controls the published host port.

## Native Go

Install Go 1.22 or newer and a C compiler with CGO enabled. Run commands from the repository root. Generate the local certificate once, then start the standard forum:

```powershell
go run ./cmd/certgen
go run .
```

Standard storage defaults to `data/forum.db`. To run a separate demo:

```powershell
go run ./cmd/seed-demo -database data/demo.db
$env:DATABASE_PATH = 'data/demo.db'
go run .
```

To switch back to standard storage after stopping the demo, run `Remove-Item Env:DATABASE_PATH` and `go run .`. Native runs use https://localhost:8080 by default. `FORUM_ADDR`, `TLS_CERT_FILE`, and `TLS_KEY_FILE` can override the listener and certificate paths.

If a local development certificate already exists, reuse it. The certificate generator refuses to overwrite existing files; choose new `-cert` and `-key` paths when renewing, then set the matching environment variables.

Use `go run ./cmd/admin -email your-account@example.com` to promote an account in the currently selected database. In Docker, use `docker compose exec forum /app/admin -email your-account@example.com`; include `-p yaplane-community-demo` for that project. Keep shared demo accounts as ordinary members.
